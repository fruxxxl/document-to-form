# Из документа в форму

Небольшой открытый инструмент для переноса реквизитов из изображения карточки организации. Браузер распознаёт текст, выделяет название, ИНН и КПП. Пользователь сверяет поля с исходником, исправляет ошибки и подтверждает перенос в демонстрационную форму.

[Открыть инструмент](https://fruxxxl.github.io/document-to-form/) · [Об авторе](https://procesa.ru/about/) · [Автоматизация ваших документов](https://procesa.ru/services/form-filling/)

English: a browser-only OCR example for Russian company cards. Extract three labelled fields, review the source text, confirm each value, and fill a demonstration form. Documents stay in the browser; OCR assets are served from the same origin.

## Запуск

Нужен Node.js 20.19+ или 22.12+. Установка зависимостей загружает Tesseract.js и русскую/английскую языковые модели.

```sh
npm ci
npm run dev
```

Откройте адрес, который напечатает Vite. Выберите один из трёх вымышленных примеров или загрузите PNG, JPG, WebP. Нажмите «Прочитать документ», проверьте поля и отметьте подтверждения. После переноса можно скопировать значения или скачать JSON.

## Границы примера

- Одна карточка юридического лица с подписанными полями «Наименование» или «Организация», «ИНН», «КПП». ИНН только из 10 цифр; КПП только из 9 цифр.
- Печатный текст. PDF, рукописные документы, таблицы и произвольные бланки не поддерживаются этой версией.
- OCR может ошибаться. При нескольких разных значениях поле остаётся пустым до решения пользователя. Рядом выводится прочитанный текст; его также нужно сверить с изображением.
- Контрольная цифра ИНН помогает найти опечатку, но не подтверждает существование организации. Проверка КПП ограничена форматом.
- Результат передаётся в форму на этой же странице. Интеграция с внешней системой в проект не входит.

Здесь используется Tesseract OCR и правила выделения полей, без LLM. Ввод пользователя и распознанный текст отображаются как текст, без выполнения HTML. Файлы не отправляются на сервер; в проекте нет аналитики. Браузер запрашивает сам сайт, WASM и языковые модели, а модели может хранить в своём кэше. Первый запуск зависит от сети и мощности устройства.

Для рабочего внедрения потребуется проверить документы заказчика, согласовать поля и подключение к его программе. Пример показывает конкретный механизм, но не подтверждает качество на других документах.

## Проверка

```sh
npm test
npm run build
npm run test:ocr
```

`npm test` проверяет извлечение, отсутствие полей, противоречия и валидацию. `test:ocr` запускает реальное распознавание трёх изображений из `public/examples/` и сохраняет наблюдения в [docs/ocr-results.json](docs/ocr-results.json). Совпадение названия сравнивается без типографических кавычек. Набор содержит только три синтетических документа, поэтому его результат нельзя считать оценкой точности на документах компаний.

Примеры создаются командой `npm run fixtures`. Изображения и ожидаемые значения хранятся в репозитории. Цифры и названия предназначены для тестирования и не удостоверяют реквизиты реального юрлица.

## Устройство

- `src/extract.ts`: выделение подписанных полей и проверка значений.
- `src/main.ts`: загрузка изображения, OCR, проверка и перенос.
- `scripts/prepare-ocr.mjs`: копирование движка и моделей из зависимостей для размещения на собственном сайте.
- `scripts/ocr-smoke.ts`: воспроизводимая проверка распознавания.

Для размещения в подпапке передайте Vite `--base=/document-to-form/`. GitHub Actions собирает и публикует статическую страницу через GitHub Pages. Сервер приложения, ключи моделей и платные API не нужны.
